# Бизнес-задача

## Контекст

Наша компания разрабатывает внутренний веб-сервис для хранения личных заметок сотрудников.

Сервис должен помочь сотрудникам быстро создавать, редактировать и хранить свои рабочие заметки.

На текущем этапе необходимо реализовать базовую функциональность управления заметками.

---

## Требуемый результат

Пользователь должен иметь возможность:

- просматривать список своих заметок;
- создавать новую заметку;
- редактировать ранее созданную заметку;
- удалять свою заметку.

---

## Ограничения

Каждый пользователь должен иметь доступ **только к своим заметкам**.

Пользователь **не должен иметь возможность** просматривать, изменять или удалять заметки других пользователей.

---

## Пользовательский сценарий

1. Пользователь открывает страницу "Мои заметки".

2. Пользователь видит список всех своих заметок.

3. Пользователь нажимает кнопку "Создать заметку".

4. Вводит:

- заголовок;
- текст заметки.

5. После сохранения новая заметка должна сразу появиться в списке.

6. Пользователь может изменить любую ранее созданную им заметку.

7. Пользователь может удалить любую ранее созданную им заметку.

---

## Нефункциональные требования

Система должна:

- корректно обрабатывать ошибки при выполнении операций;
- отображать пользователю понятные сообщения в случае возникновения ошибок;
- быть подготовлена к дальнейшему развитию проекта;
- иметь понятную и поддерживаемую структуру кода.

---

## Что не входит в задачу

В рамках данной задачи **не требуется**:

- регистрация пользователей;
- авторизация;
- поиск заметок;
- сортировка;
- категории;
- вложения;
- совместный доступ.

---

## Критерии приемки

Функциональность считается реализованной, если:

- пользователь может создать заметку;
- пользователь видит созданную заметку;
- пользователь может изменить свою заметку;
- пользователь может удалить свою заметку;
- пользователь не может получить доступ к чужим заметкам;
- интерфейс остается работоспособным при возникновении ошибок.
